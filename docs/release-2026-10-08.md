## Implemented behavior

- Public vehicle enquiries retain source/campaign, vehicle, intent and consent context.
- Staff stage, ownership, notes and follow-ups persist.
- Staff-confirmed showroom visits/test drives persist; status changes are audited. Scheduling creates an internal reminder task.
- A verified sale records INR proceeds, actual sale time and confirming staff. It atomically marks Won, archives sold inventory, closes open follow-ups and records audit/history.
- Identical sale retries return the same sale; changed details conflict. Ordinary lead/stock updates cannot reopen confirmed sales.
- Browser inventory price/publication/availability controls persist in demo and PostgreSQL and propagate to the owned website.
- New `/command/intelligence` shows recorded stock quality, price history, record age, follow-up exceptions and exact buyer constraints. It discloses unknown acquisition age/cost/market/AI coverage.
- Native Tauri UI uses the same visit and sale APIs. Its scoped Rust API allowlist has regression tests.
- Local launcher detects occupied ports, binds to loopback, reports successful readiness and forwards shutdown. Demo state uses an atomic replacement plus writer lock; it is not a production database.
- Malformed/unavailable public enquiries return safe errors. Follow-up dates are converted from browser-local time to UTC.

## Run on your machine

From an existing checkout, first commit or stash any unrelated local changes:

```bash
git fetch origin
git switch --track origin/feat/demo-connected-sales
corepack enable
corepack prepare pnpm@10.17.1 --activate
pnpm install --frozen-lockfile
pnpm demo
```

If the branch already exists locally, use `git switch feat/demo-connected-sales` then `git pull --ff-only origin feat/demo-connected-sales`.

Open website `http://127.0.0.1:3000`, Command Center `http://127.0.0.1:3001/command`, and Platform `http://127.0.0.1:3002/platform`. Keep the terminal open. Stop with Ctrl+C. Demo authentication must stay on loopback.

Walkthrough: inventory → vehicle → enquiry → lead ownership/note → follow-up → confirmed visit → actual visit status → verified synthetic sale → public delisting → confirmed-sale reporting. Use another car for inventory editing and inspect Intelligence.

## Migration and operating instructions

Run `pnpm db:migrate` from a private-network staging executor with migration credentials managed outside chat/repository. Apply `0003_sales_inventory_history.sql`, then run `pnpm db:provision-role` for a new application role. The application secret must identify `vandlabs_app`, never a superuser/BYPASSRLS account. New sales/history records force RLS and tenant-aware foreign keys; application grants are read/insert only.

Follow `production-runtime.md` for empty reference seed, tenant configuration and Cognito subject provisioning. Existing migrations remain immutable. No destructive migration or data reset was executed against a live database.

A sale correction/reversal is not implemented: do not manipulate database records to bypass the conflict guard. The production reversal workflow requires separately authorized accounting/inventory behavior.
